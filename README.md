# 2DBattle

ブラウザで動く2D格闘ゲーム。操作はスマブラ式（方向＋ボタン）、勝敗はスト式（体力制・2ラウンド先取）。
CPU対戦 / 2P対戦 / トレーニング / オンライン対戦に対応。

## 起動

```
npm install
npm start        # http://localhost:3000
```

Railway では GitHub 連携でそのままデプロイできる（`npm start`、ポートは `PORT` 環境変数）。

## 操作

| | P1 | P2 |
|---|---|---|
| 移動 / ジャンプ / しゃがみ | A D / W / S | ← → / ↑ / ↓ |
| 弱 / 中 / 強 | J / K / L | , / . / /（テンキー 1 2 3） |
| 技 | U | ;（テンキー 4） |
| 必殺技（ゲージMAX） | I | :（テンキー 5） |

- ガード：後ろ入れ。下段はしゃがみガード、ジャンプ攻撃は立ちガード
- 技：技ボタン＋なし/↓/↑/→ ＝ 波動弾 / スライディング / 昇竜拳 / 突進拳
- キャンセル：弱→中→強、通常技→技、技→必殺技
- F2：当たり判定・フレーム情報の表示

## 構成

| ファイル | 役割 |
|---|---|
| `public/sim.js` | ゲーム本体。`step(state, [p1入力, p2入力])` で1フレーム進む。整数演算のみの決定論 |
| `public/net.js` | オンライン同期（ロックステップ・可変ディレイ）。DOM非依存 |
| `public/main.js` | 入力・描画・接続（WebRTC／WebSocket） |
| `server.js` | 静的配信＋相手探し・合図・中継の WebSocket（ルーム制） |
| `test/` | 同期のテスト |

## オンラインの仕組み

互いに「Nフレーム目の入力」だけを送り合い、両方そろったフレームだけ `step()` を進める（ロックステップ）。

- 入力はブラウザ同士が直接送り合う（WebRTC）。サーバーは相手探しと接続の合図だけ
- 直接つながらない回線では、3秒後にサーバー中継（WebSocket）へ自動で切り替わる
- 入力を何フレーム先に予約するかは ping から自動調整する（遅い回線でもスローにならず、操作が少し重くなるだけ）
- 画面上のステータスに「P2P直結 / サーバー中継」「ping」「入力遅延」が出る

テスト：`npm test`（遅延・ロスのある回線を模擬）、`node test/lockstep.test.js`（サーバー中継の一致確認）

`sim.js` を変更するときの決まり：
- 小数・`Math.random()`・時刻を使わない（乱数は `rnd(s)`）
- 状態は `state` の中だけに持つ（グローバル変数に持たない）
